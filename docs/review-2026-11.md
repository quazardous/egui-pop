# Outside review, checked against 0.11 (November 2026)

An outside review of egui-pop, written against 0.3.0, rated the
architecture well (a model independent of egui, commands as one contract
for menus, keys, the palette and agents, DTCG tokens, hooks that observe,
veto, replace and extend, an application agents can drive, the
discipline of [upstream workarounds](upstream.md)) and named five
concerns: scope, layering for adoption, the API surface, the agent
bridge's security, and the checks to run before adopting it.

This page checks each concern against egui-pop 0.11 as it stands, with
the evidence, and names the follow-up for what is still open. Status:
**done** (decided and tested), **partly** (decided or built, with a gap
named), **open** (not addressed yet).

## 1. Scope

The review: windows, docking, focus, undo, clipboard, the context stack,
selection, editors, the terminal, the viewer, the node graph and jobs
are a lot to maintain, and their interactions are where bugs live.

| Question | Status | Evidence | Follow-up |
|---|---|---|---|
| Scope and its maintenance cost | partly | Each family is its own crate in a strict layering, checked by a test ([ADR 0001](adr/0001-layering.md), `crates/egui-pop/tests/layering.rs`); the interactions are decided in ADRs (context stack 0012, mount contract 0013, undo 0014, clipboard 0015, application windows 0025); most families are marked experimental ([stability](stability.md)). Nothing says which components egui-pop commits to keep, or when one would leave the repository. | A scope and support policy per component family (an ADR). |
| Undo: owned by an editor or the global store? | done | [ADR 0014](adr/0014-undo.md): a `History` owner behind `Host::history()`, scopes picked by focus, innermost first (a text field's own undo, then a component's local scope, then the owner's active scopes). Tests: `ctrl_z_goes_to_the_focused_local_scope_else_the_application`, `a_text_field_keeps_its_own_undo_inside_a_local_scope` (`crates/egui-pop-api/tests/history.rs`), `the_settings_keep_their_own_undo_apart_from_the_host_s` (`tests/undo.rs`). | None. |
| Focus when a panel is detached | done | [Workbench, the focused panel](workbench.md#the-focused-panel): egui keeps a focus per window; a widget taking the focus, a press, or the window getting the system focus back moves `focusedPanel`; `<panel>.focus` raises the panel's window. The per-window focus workaround is in [upstream.md](upstream.md) (`focus::focused_in_window`). Tests: `crates/egui-pop-core/tests/focus_windows.rs`, `crates/egui-pop-api/tests/auxiliary.rs`. | Real windows: see 5.6. |
| A shortcut claimed by several plugins | done | [ADR 0007](adr/0007-key-resolution.md): the winner is the greatest `(depth, layer, specificity, declaration order)`, every resolution can be traced; `Keymap::conflicts` and `conflicts_by_scope` (`crates/egui-pop-model/src/keymap.rs`) list the pairs, `AppHandle::key_conflicts` publishes them and the shortcuts editor shows them. | None. |
| A plugin removed while a command still refers to it | partly | [ADR 0004](adr/0004-plugins.md): everything a plugin registers is removed with it (`remove_owner` on every registry); a menu item naming an unknown command is greyed and reported (`unknown-command`); running an undeclared command fails loudly ([ADR 0003](adr/0003-no-silent-no-op.md)). Tests: `everything_a_plugin_registers_goes_away_with_it`, `disconnecting_a_plugin_disconnects_those_requiring_it_first` (`crates/egui-pop-api/tests/api.rs`). Not decided: what happens to work in flight when a plugin goes (commands queued with `run_as`, an open dialog bound to its command, its steps in a history, its jobs, user key bindings naming its commands). | An ADR on in-flight work of a removed plugin, with tests. |

## 2. Layering for adoption

The review: three tiers (foundation: model, commands, events, themes,
focus; application framework: plugins, windows, docking, persistence;
kits: components, editors, views), and components usable without
adopting `App`.

| Question | Status | Evidence | Follow-up |
|---|---|---|---|
| Clear tiers | done | [ADR 0001](adr/0001-layering.md) stacks the crates L0 to L6: tokens and the hook kernel without egui (L0), the model without egui (L1), core with theme, focus, keys and persistence (L2), the application API (L3), components and plugins (L4), the facade (L5). The layering test refuses back-edges. | None. |
| Components without `App` | partly | [Using parts without App](standalone.md) lists every part usable alone with its entry point; its examples are compiled and run (`cargo test -p consumer-smoke --doc`). Gaps: `egui-pop-views` and `egui-pop-editors` depend on `egui-pop-api` even when used without `App`; the facade always pulls `egui-pop-api` (only the component crates are optional features); no CI job builds a crate with `--no-default-features` or checks that taking only tokens or core stays light. | Move the standalone parts of views and editors off `egui-pop-api` (or behind a feature), and a CI check of the light dependency sets. |

## 3. API surface

| Question | Status | Evidence | Follow-up |
|---|---|---|---|
| Stability tiers exist | done | [API stability](stability.md): stable, supported, experimental, item by item; the README's table repeats them; releases are checked by `cargo semver-checks` ([releasing](releasing.md)). | None. |
| Applications kept off experimental parts | open | The tiers are documentation only: nothing in the code marks an experimental item (no feature gate, no attribute, no rustdoc badge), and no check fails when a stable item exposes an experimental type. The workbench, the views, the editors and the platform services are all reachable from the default facade. | Mark experimental items in code (an opt-in feature or a rustdoc marker) and a check that stable items do not expose them. |

## 4. Agent bridge security

The review: "The agent is an actor, not an implicit admin": permissions
per command, parameter validation, the origin of each action, an
operation journal, confirmation for destructive actions, undo.

| Question | Status | Evidence | Follow-up |
|---|---|---|---|
| Permissions per command | partly | `CommandSpec::agent` and `.no_agent()`, collector actions' `ActionSpec::agent` ([ADR 0018](adr/0018-agent-collector-actions.md)); the flag holds for every run, chained ones included ([ADR 0021](adr/0021-origin-along-the-chain.md)); bridge modes `On`, `ReadOnly`, `Off` with `CommandSpec::read_only` ([ADR 0024](adr/0024-bridge-modes-and-read-only-commands.md)); value writers per path ([ADR 0016](adr/0016-one-writer-per-value.md), [0019](adr/0019-actions-act-as-their-caller.md)). Tests: `crates/egui-pop-api/tests/bridge_modes.rs`, `agent_actions.rs`, `origins.rs`. Gap: one yes or no for all agents; no grants per agent or per session. | Agent bridge security design. |
| Origin of each action | partly | `Origin` (user, agent, script, remote) travels with every command, write, dialog answer, file choice and history step (ADRs 0019, 0020, 0021); the history panel names it. Gap: every client of the socket is the same `Origin::Agent("agent-socket")` ([agent socket](agent-socket.md)), so two agents cannot be told apart. | Agent bridge security design. |
| Parameter validation | open | `CommandSpec::args` is a description ("free JSON, a schema or an example", `crates/egui-pop-model/src/commands.rs`); nothing checks a call's arguments against it before the handler runs. | Agent bridge security design. |
| Operation journal | done | Every call is a `debug.call` step and is journaled; refusals are `debug.call.refused`, `command.refused`, `dialog.answer.refused`; reads are journaled only when they fail or are vetoed (ADRs 0018, 0024). | None. |
| Confirmation for destructive actions | partly | Possible by hand: a dialog answered by the user only, or a veto on `dialog.answer` unless the origin is the user, as the links plugin does ([agents](agents.md), "Keeping an action off the agent surface"). Gap: no `destructive` flag on `CommandSpec`, so nothing asks the user before an agent's destructive command runs unless each application wires it. | Agent bridge security design. |
| Undo | done | Agent steps go into the same histories, named by origin; undo and redo are held to the walker's writer ([ADR 0023](adr/0023-every-command-through-the-host.md)); `history.undo` with `if_rev` and `dry_run` for agents (`the_store_owner_answers_dry_runs_and_stale_requests`, `tests/history.rs`). | None. |
| Transport | partly | Unix socket mode 0600 in the runtime directory. On Windows the named pipe keeps the system's default access and is compile-checked only ([agent socket](agent-socket.md), "Known gaps"). | Agent bridge security design. |

## 5. Checks before adoption

| Check | Status | Evidence | Follow-up |
|---|---|---|---|
| 5.1 Cost of `DefaultPlugins` and default features; compile time; optional dependencies leaking | open | `MinimalPlugins` exists beside `DefaultPlugins` ([plugins](plugins.md)); every optional dependency sits behind a facade feature (`crates/egui-pop/Cargo.toml`). Nothing measures the build time, dependency count, binary size or start-up time per feature set, and no CI job builds with `--no-default-features`. | A box job measuring them per feature set, with a budget. |
| 5.2 Virtualised views with large collections | partly | 100 000 nodes in the tree (`a_hundred_thousand_nodes_build_a_screenful`, `crates/egui-pop-views/tests/views.rs`), images in the library (`a_hundred_thousand_images_build_a_screenful`, `tests/library.rs`) and lines in the log (`a_hundred_thousand_lines_build_a_screenful`, `tests/text_log.rs`), each under 100 ms a pass. Not covered: the data table at that size, rows updated asynchronously while it scrolls, and the selection changing under load. | A box job: a 100 000-row data table with async updates and selection changes. |
| 5.3 Undo transactions, concurrent edits, changes from outside the UI | partly | Groups and merges ([ADR 0014](adr/0014-undo.md)); stale requests refused by revision (`the_store_owner_answers_dry_runs_and_stale_requests`); histories kept apart (`a_store_write_entered_in_a_history_is_undone_there_alone`). Not tested: an undo that would cross a change made outside the interface (another process, a write that is not a step), which the analysis says is refused ([ADR 0014 analysis](adr/0014-undo-analysis.md), section 7). | Tests for undo across outside changes. |
| 5.4 Persistence migrations across versions | partly | Versioned documents and migrations ([ADR 0008](adr/0008-persisted-documents.md)); unit tests of the mechanism (`documents_migrate_and_refuse_what_they_cannot_read` in `egui-pop-model/src/doc.rs`, `documents_are_written_atomically_with_a_backup_and_migrated_on_load` in `egui-pop-core/tests/core.rs`, `an_old_keymap_document_with_the_placeholder_key_migrates`, `an_older_item_is_migrated_before_it_is_pasted`). Not covered: documents written by earlier released versions (layout, keymap, settings, arrangements) loaded by today's code. | Golden fixtures from each release, loaded by a test. |
| 5.5 Accessibility with a real screen reader | open | The test kit checks that every interactive node has a name and dumps the AccessKit tree (`egui-pop-test`); no pass with Orca, NVDA or VoiceOver is recorded. | A screen reader pass: Orca through AT-SPI on the box, NVDA on Windows. |
| 5.6 Secondary windows, focus, resize and scaling on Linux and Windows | partly | `tools/window-smoke.py` opens the gallery in a real window on Windows and macOS, detaches a panel into a second window and resizes ([testing](testing.md), "Other platforms"); in-process tests cover detached panels (`crates/egui-pop-api/tests/auxiliary.rs`, `app_windows.rs`). Not covered in real windows: focus moving between windows, keys reaching the detached window, scale factors (mixed DPI), and the same run on Linux. | Extend the window smoke run (focus, keys, scale) and run it on Linux in the box. |
