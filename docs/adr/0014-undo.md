# 0014: Undo: histories owned by the kernel, routed by focus, projected by the interface

Date: 2026-10-14. Status: accepted (2026-10-14), with the answers to
its open questions under "Decisions on the open questions" below.

The analysis behind it (what exists today, a survey of six
applications, the eight questions answered, the flows) is in the
[appendix](0014-undo-analysis.md). Where they differ, this page wins.

## Context

egui-pop has five undo histories that do not know each other: the value
store's `Step` stacks (reached by `edit.undo` through `Host::undo`), the
theme editor's `ThemeDraft`, the code editor's `History`, egui's own
`TextEdit` undoer, and the settings window's `value.undo`. Only the
first answers Ctrl+Z; inside the theme editor, Ctrl+Z undoes an
unrelated store step. None is capped, none is persisted, and nothing
lets a host add an entry it made itself (a network edit, an import, an
agent's request). The context stack (ADR 0012) needs each step to know
the place it was made in, and today guesses it by counting store steps.

An application with a kernel (Helios) keeps its own durable histories
(an image's edit as a line of versions, an audit of library fields, a
workspace's states), runs agents that edit through the same commands as
the user, and may run edits in another process. Undo has to be the
kernel's, as the context stack is; the interface routes keys to it and
shows it.

## Decision

**A typed contract, implemented by the kernel, with a local default.**
The owner implements `History` (in `egui-pop-api`, reached through
`Host::history()`, like `Host::contexts()`): its **scopes**, their
**steps**, and the requests `undo`, `redo`, `jump`, `group`. egui-pop's
default owner, `StoreHistory`, keeps today's behaviour over the value
store. The pure parts (`ScopeId`, `StepInfo`, `Label`, the merge rules,
the `history` document for a local owner) live in
`egui-pop-model::history`.

**A scope is one history.** It has an id, a title, the focus targets
that select it (panels, components), whether it survives a restart, and
its limits. Examples: a document (an image's edit), a collection (a
library's marks), a workspace, the settings window. Steps never cross
scopes, except a group that spans several (one entry in each, undone
together or refused, as VS Code's workspace edit).

**A step says what it is, not how to undo it.** The interface sees a
`StepInfo`: id, scope, label (a message id and its arguments, rendered
in the interface's language: "Exposure +0.30 EV"), origin (user, agent
and its session, script, remote), group (the request it belongs to),
the frame path it was made in (ADR 0012), its time, and whether it is
"in progress". The inverse lives with the owner.

**Focus picks the history.** Ctrl+Z resolves, innermost first:

1. a focused text input keeps its own undo (egui's undoer; the code
   editor's `History`), as today (`!textInputFocus`);
2. a focused component with a **local scope** (the theme editor's
   draft, the settings window) undoes there; a local scope is
   registered by the component (`Ctx::local_scope`, a `LocalScope`)
   and lives in the interface, never persisted;
3. otherwise the owner's scopes **active in the window** (those whose
   focus targets are shown: the image shown, the library, the
   workspace): Ctrl+Z undoes the **newest** step among them. A step of
   a scope not active (another image) is not reachable by Ctrl+Z; it
   is reached by opening that document, or through the history panel.

A step made in another place of the context stack is undone where it
was made, and a toast says "Undone in <place>" with "Go there" (ADR
0012, now read from the step's frame path, not counted).

**Grouping is declared, not guessed.** A gesture is one step (drag,
Escape cancels and leaves none). Repeats on one target (held arrows,
wheel notches, a colour picker's frames) merge while they keep the same
merge key and come less than a second apart, or until focus leaves.
`group(origin, label)` opens an explicit group (an import, an agent's
request, a workspace merge): every step made under it is one entry,
named by the group. A group left open by an origin that went away is
closed by the owner when the origin ends, never by the interface.

**Redo is linear; nothing is lost.** A new step after an undo drops the
redo list of that scope. An owner whose history is durable may keep
every state reachable another way (Helios's versions are append-only),
and offers **snapshots**: named states pinned in a scope, never dropped
by a cap. No non-linear history.

**Persistence is the scope's.** A scope declares whether it survives a
restart; one that does rebuilds its undo and redo lists on reopen, so
Ctrl+Z after a restart walks back the same steps. Each scope has a cap
in memory (default 500 entries, the host may set another); an owner
with a durable history may page older entries in when the history
panel scrolls. "Compress" is the owner's (it rewrites what it stores),
not the contract's.

**Undo, redo and jump are steps** (ADR 0011): `edit.undo`, `edit.redo`,
`edit.jump`, with the scope and step in their arguments, vetoable (a
gesture in progress vetoes them; `StoreHistory` does it too, so an undo
can no longer write into the user's own drag). They publish
`history.changed` (the scope, its new head and revision),
`history.refused` (with the reason: a held path, a later step on the
same target, another process) on the journal; every reader folds them.

**The projection** comes with `HistoryPlugin`: the Edit menu's labels
("Undo Exposure +0.30 EV"), the keys `canUndo`, `canRedo` and
`historyScope`, a `HistoryView` panel (a scope's steps, grouped and
attributed, a click to jump, a hover to preview through the owner, a
snapshot button), the "Go there" toast, the commands `history.*` for
agents (list, undo, redo, jump, snapshot, each with `if_rev` and
`dry_run`), and a `history` collector on the debug bridge.

**Survey.** undo (MIT or Apache, a command-pattern `Record` and a
branching `History`), undo_2 (Emacs-style undo that never loses a
state; licence to check before any use),
and egui's own `Undoer` (state snapshots, one widget) all keep the
inverse in the interface's process and assume one owner of the state.
Here the state, its inverse and its persistence are the kernel's, and
may be in another process. **Own** the contract and the panel; an owner
may use either crate inside.

## Consequences

- One Ctrl+Z rule for every application, with text fields and local
  editors keeping their own; the theme editor's Ctrl+Z works.
- A host can at last add entries (network edits, imports, agents'
  requests) and name them; agents read and drive the same history as
  the panel.
- `Host::undo` and `Host::redo` are replaced by `Host::history()`; the
  value store's stacks become `StoreHistory`'s one scope, capped.
- The code editor, the theme editor and the settings window register
  local scopes; their own models stay as they are.
- Undo across processes is the owner's affair: the contract only asks
  it to refuse with a reason, and the interface shows the reason.

## Decisions on the open questions

The owner's answers (2026-10-14), for egui-pop and for Helios, its
first host:

1. **The network in a version** (Helios): each version keeps the whole
   network; an image keeps its own once edited.
2. **A collection's marks**: undoable for the session only; restoring
   them from the audit trail after a restart comes later.
3. **Which Ctrl+Z wins**: after a focused text input and a focused
   local scope, the newest step among the scopes active in the window.
4. **Compress history**: not for now.
5. **Dropped redo states** of a durable owner: hidden in the history
   panel, with a toggle that shows them as "replaced" rows.
6. **A copy-import undone** removes the catalogue entries only, never
   the files.
7. **The cap**: 500 steps per scope, and a host can change it.
8. **The code editor** keeps its own local scope (its `History`,
   1000 entries, Ctrl+Z while it has the focus).

## Done ahead of the steps

Fixes found while reading the code, made before step 1 (2026-10-14):

- The value store refuses an undo or a redo that would write into a
  gesture still going, the user's own included (`Refused::Held`).
- The value store keeps its newest 500 steps and the theme draft its
  newest 500 edits (`HISTORY_CAP`, `DRAFT_HISTORY_CAP`); a host sets
  another cap with `set_history_cap`; the context stack drops the
  places it keeps beside the steps the cap drops (`dropped_steps`),
  still matched by count until step 3. A host adding entries of its
  own waits for the `History` contract (step 1).
- The theme editor is a focus surface where Ctrl+Z, Ctrl+Shift+Z and
  Ctrl+Y run `theme.undo` and `theme.redo`: its local scope, ahead of
  the routing of step 2.
