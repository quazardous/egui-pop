Files dropped from another program are on the bus, on every window. Each window's pass (the main window, an application window, a detached panel's window) reads the files the system drops on it once, as that window's `files.drop` request (`bus::FilesDrop`, a `bus::FileDrop` naming the window, the paths and the pointer); whoever takes them is a listener and says so in the value; then `files.dropped` is said with what they did, or `files.refused` when nobody took them or the window is not open. Before, only a file browser drawn in the window saw a drop, and files dropped on a window without one went unsaid. The file browser no longer reads egui's dropped files itself: a system drop it takes on one of its targets is said by its listener `files.browser` (`bus::FILES_BROWSER`), first, so an application's listener declared after it leaves that drop alone. While files hover a window and no widget shows where they would go, the window outlines itself and says "Drop the files here" or "Nothing here takes files". New: `AppHandle::request_files_drop`, `bus::FILES_POINTS`, and `bus::asking`, the application whose request runs now, for an application's listener that keeps no handle. `bus::POINTS` gains `files.drop` (its length changes). The test kit's `MultiWindow::hover_files` and `MultiWindow::drop_files` give a window's next pass files hovering it or dropped on it.
