The active window is on the bus (ADR 0029). Which window the person works in is asked with the new `window.activate` request (`bus::WindowActivate`, `AppHandle::request_window_activate`), reasons `user` (a press, a key or text in the window), `system` (the window gained the system's focus, asked once) and `command` (the application asks it to the front); the registry holds it, and `window.activated` is said when it changed (`window.refused` for a window not open). `AppHandle::active_window` reads the registry, `AppHandle::active_window_id` gives its id, and `windows.list` marks it (`WindowRecord::active`). A command's `window.activate` is raised by the bus's listener `bus::RAISE` (`window.raise`: shown, restored, focused; attention asked on Wayland for the main window), the one place egui-pop sends `ViewportCommand::Focus`: `AppHandle::raise_window`, an application window opened again, a panel asking the focus and a click on a blocked window's backdrop all ask it. On `window.close`, `window.focus` hands the activation to the window worked in before, for every kind of window (detached panels' included), by its own `window.activate`. `egui-pop-platform`: the second launch, the tray and notifications raise the application through `window::raise_app` (its `window.activate`); `window::raise` stays for a program without an application. `egui-pop-core`: `overlay::block_window_raising` lets a modal raise its window through the application.
