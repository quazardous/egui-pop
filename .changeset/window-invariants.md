The window registry is checked against what is on screen (ADR 0029, slice 2, `window_invariants`). Five rules run at the end of every main window pass and, for the ones the registry alone answers, as the last listener of every window and popup request: the registry's windows are the backend's viewports past one pass of grace (`registry-is-backend`, skipped while viewports are embedded), a shown window paints within the paint guard's passes and delay (`shown-paints`), every window and popup has an owner (`has-owner`), a popup's parent is open (`popup-has-parent`), a closed parent leaves no live child (`no-child-of-closed-parent`). A broken rule is never fixed silently: one error line naming the rule, the window, its owner and its state, one `window.invariant` event (`rule`, `window`, `owner`, `state`), and an entry in `AppHandle::broken_invariants` (`AppHandle::invariants_broken_now` for those still broken; both in the debug bridge's `bus` collector); a line says when it holds again. Detached panels' windows are now in the registry (`panel:<id>`, kind `panel`). In the test kit, `MultiWindow` lists the windows it declared as the backend does and fails the test on a broken invariant unless the test allows its rule (`MultiWindow::allow_broken`); `assert_window_invariants` does the same for a kittest harness, and scenarios gain the built-in invariant `WindowInvariants`.
