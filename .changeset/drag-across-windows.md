egui-pop-api: major

A drag of any payload goes from one window to another (`bus::drag`). Before, egui's own drag payload lived in the passes of the window the drag began in: the system keeps the pointer there while the button is held, so a payload let go over another window (a detached panel's window, an application window) was lost; only the workbench's tabs had a way across. Now a source starts a drag session (`drag::start`, with its kind), drop targets say where they are each pass by window and by id (`drag::target`, which tells a target what it sees: over it, maybe over it where the system hides where windows are, dropped, or refused with its reason), and the payload let go is delivered once to the target under the pointer: in its own window, in the window the screen's coordinates place it in, or, where the system hides window positions (Wayland), in the first window that sees the pointer over a target once the drag lets it go. On the bus: `drag.start` (`bus::DragStart`, its kind and window) then `drag.started`; `drag.drop` (`bus::DragDrop`, the window and the target, egui-pop's listener `drag.target` first) then `drag.dropped`; a target refusing it, a drag let go over nothing or cancelled with Escape is `drag.refused` with the reason. Where a drag hovers each pass stays off the bus. The workbench's tabs and tab groups go through the same session (kinds `tab` and `tab-group`), its detached windows being their targets. New: `bus::DRAG_POINTS`, `drag::payload`, `drag::active`, `drag::ended`, `drag::take_ended`, `drag::claim`. `bus::POINTS` gains `drag.start` and `drag.drop` (its length changes).
