The screens are on the bus: a screen unplugged or plugged in, as told by whatever runs the event loop (`window::set_screens`), is said as `screen.removed` or `screen.added` (`bus::ScreenRemoved`, `bus::ScreenAdded`, a `bus::ScreenChange`: the name winit gives it, its rectangle in points, its scale), from the main window's next pass; both are in `bus::CONTRACT` and `bus::POINTS` (now 19 points, a breaking change for code naming the array's length; `bus::SCREEN_POINTS` lists them). On `screen.removed` a detached panel's window kept on the screen gone docks back (`workbench.screens`, the layout's rule, now fed with the screens' real names: a detached window keeps the name of the screen it is on), and every other window that meets no screen left (the main window, application windows, a detached window on a screen it could not name) moves onto one (`window.place`) and keeps that place. Where positions are hidden (Wayland) nothing moves. A window kept on a screen gone since the last run is repaired the same way once the screens are first told. Invariant 6, `window_invariants::ON_SCREEN` ("a positioned window meets a screen"), joins `window_invariants::RULES` (now 6 rules). `window::screen_name_at` names the screen a rectangle is on; `window::UNNAMED_SCREEN` is the name a layout gives a screen it cannot name. `egui-pop-test`: `MultiWindow::set_screen_list` tells named screens, `MultiWindow::outer_rect` reads a window's place, and an `OuterPosition` command moves the window as a system telling positions does.
